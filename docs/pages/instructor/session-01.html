Before you start

  • Check that everyone ran the Setup test. Anyone who didn’t should start install.packages() at the very beginning of class — it can take several minutes. Windows users may need Rtools and Mac users may need the Xcode Command Line Tools (Troubleshooting).
  • Hand out the green and red sticky notes and explain them.

Teaching notes by part

Part 1 — Project folders and here(). Show that here::here() points at the workshop folder because it’s open in Positron (and has a .here file). Learners using RStudio should open the .Rproj file instead; everything else is the same.

Positron vs RStudio names: if learners follow older tutorials, Positron’s Variables pane is RStudio’s Environment pane, and the Explorer is the Files pane.

Part 3 — R basics. Keep this brisk (about 10 minutes); learners will practice all of it in every later session. Have someone make a deliberate mistake (Mean(ages)) to show that R is case-sensitive.

Part 4 — The pipe. If anyone asks why round(38.5) gives 38 rather than 39: R rounds a 5 to the nearest even number, which avoids bias when rounding many values.

Part 6 — Inspecting. This is the longest part. The “Think about it” questions on the lesson page are prompts to ask the class:

  • What is wrong with these column names? — spaces, dots, capitals, mixed styles.
  • Which column types look wrong? — date.onset is text, age is text, and age_unit hints that some ages aren’t in years.

After skim(), point at the n_missing column, the negative minimum of wt_kg, and the near-300 cm maximum of ht_cm.

Part 7 — The problem list. Build the list with the class — ask learners to call out what they found before showing the table. Make sure they save their measles problem list: Session 2’s TRY ITs work through it.
