Part 1: R basics

Before we open any data, a few building blocks you’ll use in every line of R. Type these in your script and run each line with Cmd + Return (Mac) or Ctrl + Enter (Windows); the result appears in the Console.

Objects and the assignment arrow <-

<- stores a value in an object so you can use it later. Read it as “gets”. The object appears in the Variables pane. Shortcut: Option + - (Mac) or Alt + - (Windows) types <- for you.

👀 Follow along 1.1 — Store a number in an object called my_age, then add 5 to it.

Pattern: OBJECT_NAME <- VALUE

my_age <- 35
my_age
[1] 35
my_age + 5
[1] 40
Note🔍 What this code does
  • my_age <- 35 creates an object called my_age and stores the number 35 in it. Nothing prints: saving is silent. my_age now appears in the Variables pane.
  • my_age on its own prints what is stored: [1] 35. The [1] means “this is the first value”. It helps you keep your place when the output runs over several lines.
  • my_age + 5 uses the object in a calculation and prints 40. my_age itself is still 35: to change it, you would save again with <-.

Vectors

c() combines values into a vector. Every value in a vector has the same type. Text values need quotes: c("Central Hospital", "Other").

👀 Follow along 1.2 — Make a vector of ages with c(), then find the mean().

ages <- c(2, 18, 56, 61)
mean(ages)
[1] 34.25
Note🔍 What this code does
  • c(2, 18, 56, 61) combines four numbers into one vector, and ages <- saves it.
  • mean(ages) gives the whole vector to mean(), which adds the values and divides by how many there are: (2 + 18 + 56 + 61) / 4 = 34.25.
  • Most R functions work on a whole vector at once, so you rarely handle values one by one.

Functions and arguments

A function does something to its inputs (arguments): function_name(argument1, argument2, ...). Arguments can be named.

👀 Follow along 1.3 — Use round(3.14159) with and without digits = 2.

round(3.14159)
[1] 3
round(3.14159, digits = 2)
[1] 3.14
Note🔍 What this code does
  • round(3.14159) has one argument, the number. The digits argument wasn’t given, so round() uses its default, 0, and rounds to a whole number: 3.
  • round(3.14159, digits = 2) adds a second, named argument and gives 3.14.
  • Arguments you leave out use their default value. The help page (?round) lists every argument and its default.
TipGetting help

Type ?round in the Console to open the help page for any function.

Data frames

A data frame is a table: each column is a variable (a vector), each row is an observation. (Later you’ll also see tibbles: the tidyverse version of a data frame, which prints more neatly.)

Here is a small data frame called patients, drawn as boxes. Each column is a vector, so every value in it has the same type: name is all text and age is all numbers. Each row is one patient.

name
"Ana"
"Ben"
"Cho"
text
age
34
51
27
numbers

This is the code that makes it. You don’t need to type it: you’ll build data frames yourself in Session 4. Notice $, which pulls out one column; you’ll use it often.

patients <- data.frame(
  name = c("Ana", "Ben", "Cho"),
  age  = c(34, 51, 27)
)
patients
  name age
1  Ana  34
2  Ben  51
3  Cho  27
patients$age        # $ pulls out one column
[1] 34 51 27
WarningCommon mistakes
  • R is case-sensitive: Age and age are different
  • Object names can’t start with a number or contain spaces: age2 and my_age work, 2age and my age don’t. Avoid names R already uses, such as c, mean, or data
  • Text needs quotes ("Central Hospital"); object names do not (my_age)
  • Every ( needs a ) — Positron highlights the matching pair
  • # starts a comment; R ignores the rest of the line

Note📖 Good to know
  • Script or Console? The Console runs a line once and forgets it. Your script is the record of what you did, so type your code in the script and run it from there.
  • Objects live in R’s memory, not on your disk. They disappear when you close Positron or restart R. That’s fine: rerun your script and they’re back. If you’re ever asked whether to save the workspace, choose No.
  • <- or =? Both can store a value, but this course always uses <-, so that = only ever means “name an argument” (as in digits = 2).
  • A vector holds one type. If you mix text into numbers, R turns everything into text: c(5, 12, "unknown") is three pieces of text. You’ll see this in the practice data, where a few ages say “unknown”.

Part 2: Installing and loading packages

A package is a collection of functions someone else wrote. There are two steps:

Step Function How often Analogy
Install install.packages() Once per computer Buying a book
Load library() Every time you open R Taking it off the shelf

To install one package, put its name in quotes:

install.packages("janitor")

To install several at once, combine the names with c(), the same c() you used for vectors in Part 1. This line installs everything for the whole workshop series (skip it if you did the Setup):

install.packages(c("tidyverse", "here", "rio", "janitor", "skimr", "gtsummary", "flextable", "scales"))
Note🔍 What this code does
  • install.packages("janitor") downloads one package, janitor, from CRAN (R’s official package library, see below) and installs it on your computer. Some packages need a few others to work: R installs those too, so you may see several downloads.
  • install.packages(c(...)) does the same for every name in the list, one after the other. It can take several minutes.
  • You install a package once per computer. You only need to install it again after you install a new version of R, or to get a newer version of the package.

Load only what you need today:

👀 Follow along 2.1 — Load today’s packages, one library() line each. ✅ You should see no line that starts with “Error”.

Pattern: library(PACKAGE_NAME)

library(tidyverse)   # data wrangling (dplyr) and plotting (ggplot2)
library(here)        # file paths that work on any computer
library(rio)         # import() and export() for almost any file type
library(skimr)       # skim() for a quick data summary
Note🔍 What this code does
  • Each library() line makes one package’s functions available until you close Positron or restart R. That’s why every session starts with these lines.
  • library(tidyverse) loads a whole family of packages at once (dplyr, ggplot2, tidyr, readr, stringr, forcats, lubridate, tibble, and purrr) and lists them.
  • Its Conflicts message says that a few tidyverse functions share a name with a base R function, for example filter(). From now on, filter() means the tidyverse version. This is normal, not an error.
  • The text after # is a comment: a note for people. R ignores it.
WarningCommon mistakes
  • Package names need quotes in install.packages() but not in library().
  • Red text is not always an error! See the next section.

Error, warning, or message?

You just saw red text in the Console. Red text comes in three kinds, and each one asks something different of you:

Kind How to spot it What happened What to do
Error starts with Error R stopped. The line did nothing. Read the message, fix the code, run it again
Warning starts with Warning R finished, but something may be off Check the result: did values turn into NA, or did rows disappear?
Message anything else, like the list from library(tidyverse) Information only Nothing

The message after Error usually tells you what’s wrong, for example could not find function "Count" (R is case-sensitive: the function is count()). You’ll practise reading them in TRY IT 5.

TipAsking for help

Stuck? Put up your red sticky note. When you ask someone for help, in class, by email, or online, include three things:

  1. Which line you ran (copy it)
  2. What you expected to happen
  3. The exact message R gave you (copy it, don’t retype it)
Note📖 Good to know
  • Packages are shared on CRAN, R’s official package library, which has more than 20,000 of them. install.packages() downloads from there.
  • The tidyverse is a family of packages designed to work together, with the same style of function names and arguments. That’s why one library(tidyverse) loads several of them.

Part 3: Project folders and here()

Why keep everything in one project folder?

  • Organization: data, scripts, and outputs live in one folder with a predictable structure (raw_data/, processed_data/, student_scripts/)
  • Reproducibility: the project works on any computer — yours, a collaborator’s, future you’s
  • Shareable: zip the folder and send it, or put it on GitHub

Open the project folder for this class

  1. Download the workshop folder and save it somewhere you can find it (not your Downloads folder)
  2. In Positron, choose File → Open Folder…, select the cwml-r-workshop folder, and click Open. Positron uses that folder as the working directory
  3. Check the Explorer on the left: it should list the workshop files (raw_data, student_scripts, …)
TipYour own projects later

Make a new folder for each project (with subfolders like raw_data/ and scripts/), and open it in Positron with File → Open Folder…. Add an empty file called .here at the top so here() always finds it.

Relative vs absolute paths

  • Bad (absolute): "/Users/mwegener/Desktop/maybe_here/data.csv" — only works on one computer
  • Good (relative): here("raw_data", "data.csv") — works on any computer that has the project folder

here() finds the top of the project folder (it looks for a .here file, which the workshop folder has) and builds the path from there.

👀 Follow along 3.1 — Find the top of the project folder.

Pattern: here::here()

here::here()                                   # where is the top of my project?
Note🔍 What this code does
  • here::here() prints the full path to the top of the project folder: wherever you saved cwml-r-workshop on your computer. It finds the top by looking for the .here file.
  • If the path isn’t your workshop folder, the folder isn’t open in Positron. Choose File → Open Folder… and open it.

👀 Follow along 3.2 — Build the path to raw_data/linelist_raw.xlsx.

Pattern: here::here("FOLDER", "FILE_NAME.EXTENSION")

here::here("raw_data", "linelist_raw.xlsx")    # full path to a file inside it
Note🔍 What this code does
  • here::here("raw_data", "linelist_raw.xlsx") adds a folder and a file name to that path, joined with /. R uses / on every computer, Windows included.
  • It only builds the path, as text. It doesn’t check that the file exists or open it: that’s the job of import(), next.
  • Each piece is in quotes because it’s text, not the name of an object.

here::here() means “the here() function from the here package”. The :: lets you use a function before loading its package.

Note📖 Good to know
  • The working directory is the folder R reads files from and saves files to. Opening the workshop folder in Positron sets it for you.
  • Older tutorials often start with setwd("C:/Users/..."). That path only exists on one computer, so the script breaks everywhere else. A project folder with here() avoids this.
  • here() finds the top of the project by looking for a marker: a .here file (the workshop folder has one), an .Rproj file, or a .git folder.

Part 4: Importing data

import() + here()

rio::import() reads almost any file type (.csv, .xlsx, .txt, SPSS, Stata, SAS, …). It works out the type from the file extension, so you only need to learn one function. Save the result with <-, or it only prints to the Console and is gone.

👀 Follow along 4.1 — Import raw_data/linelist_raw.xlsx and call it linelist_raw.

Pattern: NEW_NAME <- import(here("FOLDER", "FILE_NAME.EXTENSION"))

linelist_raw <- import(here("raw_data", "linelist_raw.xlsx"))
Tip🧩 Reading a function call

Here is the line you just ran, taken apart:

linelist_raw <- import(here("raw_data", "linelist_raw.xlsx"))

Piece What it is What it does
linelist_raw the name of a new object holds the result
<- the assignment arrow saves the result in linelist_raw
import(...) a function from the rio package reads a file into R
here(...) a function from the here package, used as the argument of import() builds the full path to the file
"raw_data", "linelist_raw.xlsx" two text arguments of here() the folder, then the file name

R runs it from the inside out: first here() builds the path, then import() reads the file at that path, and finally <- saves the result. Reading code aloud in the same order helps: “linelist_raw gets: import the file at here, raw_data, linelist_raw.xlsx.”

Note🔍 What this code does
  • import() saw the .xlsx ending and read the file as an Excel workbook (the first sheet, unless you ask for another).
  • Nothing prints. linelist_raw appears in the Variables pane with 6604 rows and 12 columns.
  • The result is a data frame: the same kind of table as patients in Part 1, only bigger. Each row is one patient (a case), and each column is one piece of information about them.
WarningCommon mistakes
  • File names must match exactly, including capitals and the extension.
  • “Error: No such file” means the folder or file name is misspelled, or the workshop folder isn’t open (check the Explorer on the left).
TipOther import options you may see
  • Base R: read.csv() — older, slower, and needs more settings
  • readr: read_csv() — the tidyverse version, fast and returns a tibble
  • haven: read_sav(), read_dta(), read_sas() — SPSS, Stata, SAS files
  • Excel files with several sheets: import(here("raw_data", "file.xlsx"), which = "Sheet2")

✅ Check: in the Variables pane, measles_raw shows 1215 rows and 11 columns

NoteShow solution

Note📖 Good to know
  • import() passes the work to a specialist package based on the file ending: readxl for Excel, data.table for CSV and text files, and haven for SPSS, Stata, and SAS. You only need to remember one function.
  • import() returns a plain data frame, which prints every row. That’s why this lesson wraps long output in head(). Tidyverse functions return a tibble, a data frame that prints only the first 10 rows.
  • Excel stores dates as date-times, so most date columns arrive as <dttm>. One column, date.onset, arrives as text: Excel files often hold surprises like this, which is why you inspect before you clean.

Part 5: Inspecting data

Always look before you clean. Inspecting tells you whether the data imported correctly and what needs fixing. These are the questions to answer, for this dataset and for any dataset you work with later:

  1. How many rows and columns are there? Is that what you expected? (dim())
  2. Are the column names easy to use? Are the column types right: numbers, dates, text? (glimpse())
  3. Which columns have missing values? Are there impossible values? (skim())
  4. Are the categories spelled consistently? (count())
  5. Are there duplicate rows? (Session 3 shows how to check.)

Write down every problem you find. The answers become your problem list in Part 6.

Note🔁 The base R way: table()

You will often see base R’s table() in other people’s code. It counts too, but it hides missing values unless you ask for them. (Reading only: you don’t need to type this.)

table(linelist_raw$OUTCOME)                   # where are the missing outcomes?

  Death Recover 
   2898    2213 
table(linelist_raw$OUTCOME, useNA = "ifany")  # there they are: 1493

  Death Recover    <NA> 
   2898    2213    1493
Note🔍 What this code does
  • table() takes one column, pulled out with $, instead of the data and a column name.
  • Without useNA = "ifany", it shows only Death (2898) and Recover (2213). The 1493 missing outcomes are left out without a warning, so any percentages you worked out from it would be wrong.
  • useNA = "ifany" adds an <NA> count whenever there are missing values.

count() always shows NA. With table(), add useNA = "ifany". See Base R ↔︎ tidyverse for more translations.

Key points

  • <- saves a value in an object; functions take arguments.
  • Install a package once with install.packages(); load it every session with library().
  • A project folder plus here() makes file paths work on any computer.
  • import(here("folder", "file")) reads almost any file type.
  • Look before you clean: dim(), glimpse(), skim(), and count() find most problems.
  • An error stops the code; a warning means check the result; a message is information. Read the message: it usually says what’s wrong.
