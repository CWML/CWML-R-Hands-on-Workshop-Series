Part 2: Writing your first function

Why write functions?

If you copy and paste code more than twice, write a function. Functions:

  • avoid copy-paste mistakes (change it once, fixed everywhere)
  • give a task a clear name (c_to_f() says what it does)
  • make your scripts shorter and easier to read

The shape of a function

c_to_f <- function(temp_c) {
  temp_c * 9 / 5 + 32
}
  • c_to_f is the name — you save a function with <- like any object. Run the whole block to create it; then it appears in the Variables pane
  • temp_c is the argument — the input. Inside the function, it is whatever value you pass in
  • The code between { } is the body
  • The function returns the result of its last line
c_to_f(38)
[1] 100.4
c_to_f(c(36.8, 38.5, 40.1))   # it's vectorized, because the maths inside is
[1]  98.24 101.30 104.18

Because it’s vectorized, it works on a whole column inside mutate():

linelist %>%
  mutate(temp_f = c_to_f(temp)) %>%
  select(case_id, temp, temp_f) %>%
  head(3)
  case_id temp temp_f
1  5fe599 36.8  98.24
2  8689b7 36.9  98.42
3  11f8ea 36.9  98.42

Default values

Give an argument a default with =. You can change it, but you don’t have to:

c_to_f <- function(temp_c, digits = 1) {
  round(temp_c * 9 / 5 + 32, digits)
}

c_to_f(38.37)              # uses digits = 1
[1] 101.1
c_to_f(38.37, digits = 0)  # overrides it
[1] 101
WarningCommon mistakes
  • Changing the function but not re-running the block: R still uses the old version.

A function that takes a data frame

hospital_summary <- function(data, hospital) {
  data %>%
    filter(hospital_name == hospital) %>%
    summarise(
      n         = n(),
      pct_death = pct(outcome == "Death")
    )
}

hospital_summary(linelist, "Military Hospital")
    n pct_death
1 896      44.5
hospital_summary(linelist, "Central Hospital")
    n pct_death
1 454      42.5

hospital is an argument holding a value (the hospital’s name), so it can go straight into filter().

A function that makes a plot

make_epicurve <- function(data, hospital) {
  data %>%
    filter(hospital_name == hospital, onset_date >= as.Date("2014-01-01")) %>%
    ggplot(aes(x = onset_date)) +
    geom_histogram(binwidth = 7, fill = "#2a78d6", color = "white") +
    labs(
      title = paste("Weekly cases:", hospital),
      x     = "Week of onset",
      y     = "Number of cases"
    ) +
    theme_minimal()
}

make_epicurve(linelist, "Military Hospital")

paste("Weekly cases:", hospital) builds the title from the argument, so every plot gets the right title.

WarningCommon mistake: name the argument district_name, not district

Don’t give an argument the same name as a column! In

function(data, district) { data %>% filter(district == district) }

R compares the district column with itself, so every row is kept — no error, just the wrong answer. Name the argument district_name instead: filter(district == district_name).

Part 4: if / else

if runs code only when a condition is TRUE. else runs when it’s FALSE:

fever_status <- function(temp) {
  if (temp >= 38) {
    "fever"
  } else {
    "no fever"
  }
}

fever_status(39.2)
[1] "fever"
fever_status(36.9)
[1] "no fever"

if works on ONE value

fever_status(c(39.2, 36.9))
Error in `if (temp >= 38) ...`:
! the condition has length > 1

if asks one yes/no question. For a whole column, use the vectorized if_else() from Session 2:

fever_status <- function(temp) {
  if_else(temp >= 38, "fever", "no fever")
}

fever_status(c(39.2, 36.9))
[1] "fever"    "no fever"
linelist %>%
  mutate(fever_measured = fever_status(temp)) %>%
  count(fever_measured)
  fever_measured    n
1          fever 4976
2       no fever 1324
3           <NA>  151

Where if shines: checking inputs

if is perfect for questions with one answer, like “is the input a number?”. stop() ends the function with a helpful error message:

c_to_f <- function(temp_c, digits = 1) {
  if (!is.numeric(temp_c)) {
    stop("temp_c must be a number, not ", class(temp_c))
  }
  round(temp_c * 9 / 5 + 32, digits)
}

c_to_f("38")
Error in `c_to_f()`:
! temp_c must be a number, not character

Part 5: for loops

A for loop runs the same code once for each value in a vector:

for (h in c("Central Hospital", "Military Hospital")) {
  print(h)
}
[1] "Central Hospital"
[1] "Military Hospital"

Read it as: “for each h in this vector, run the code between { }”. h takes each value in turn.

Loop over every hospital

hospitals <- linelist %>%
  filter(hospital_name != "Other/Unknown") %>%
  distinct(hospital_name) %>%
  pull(hospital_name) %>%
  sort()

hospitals
[1] "Central Hospital"              "HMO Health"                   
[3] "Military Hospital"             "Premiere Health"              
[5] "Regional Medical center"       "St. Mark's Maternity Hospital"
for (h in hospitals) {
  n_cases <- sum(linelist$hospital_name == h)
  print(paste(h, "has", n_cases, "cases"))
}
[1] "Central Hospital has 454 cases"
[1] "HMO Health has 280 cases"
[1] "Military Hospital has 896 cases"
[1] "Premiere Health has 274 cases"
[1] "Regional Medical center has 1771 cases"

Inside a loop, results are not printed automatically — use print().

Save the results

To keep results, create an empty container before the loop and fill it inside:

case_counts <- c()   # an empty vector

for (h in hospitals) {
  case_counts[h] <- sum(linelist$hospital_name == h)

make_measles_epicurve <- function(data, district_name) {

    filter(district == district_name, !is.na(report_date)) %>%

Part 6: Iteration the tidyverse way: map() and walk()

The purrr package (part of the tidyverse) does what loops do, in one line:

  • map(x, f) — run f on each element of x and return a list of results
  • map_dbl() — the same, but return a number vector
  • walk(x, f) — run f on each element for its side effect (like saving a file), return nothing
# The mean of three columns
linelist %>%
  select(age_years, bmi, temp) %>%
  map_dbl(~ mean(.x, na.rm = TRUE))
age_years       bmi      temp 
 16.05732  30.59385  38.58784

A data frame is a list of columns, so map_dbl() runs once per column. ~ mean(.x, na.rm = TRUE) is a short function: .x is the current element — the same ~ .x you used with across() in Session 3.

# A list of six plots
epicurves <- map(hospitals, ~ make_epicurve(linelist, .x))
length(epicurves)
[1] 6
epicurves[[1]]
# Save them all: the same as the for loop in Part 5, in one call
walk(hospitals, ~ ggsave(
  here("outputs", paste0("epicurve_", make_clean_names(.x), ".png")),
  plot = make_epicurve(linelist, .x), width = 8, height = 5, dpi = 300
))
NoteLoop or map()?

Both are fine! Loops are easier to read when you’re starting out; map() is shorter and is what you’ll see in modern R code. Choose the one you can read.

Note🔁 The base R way: lapply() and sapply()

Base R’s apply family does the same job, and you will see it everywhere in older code, help pages, and bioinformatics packages (Bioconductor):

purrr base R returns
map(x, f) lapply(x, f) a list
map_dbl(x, f) sapply(x, f) (or vapply(x, f, numeric(1))) a vector, usually 
three_cols <- linelist[, c("age_years", "bmi", "temp")]

sapply(three_cols, mean, na.rm = TRUE)    # like map_dbl()
age_years       bmi      temp 
 16.05732  30.59385  38.58784 
lapply(three_cols, range, na.rm = TRUE)   # like map(): a list
$age_years
[1]  0 84

$bmi
[1] 10.9 60.0

$temp
[1] 35.2 40.8
sapply(three_cols, range, na.rm = TRUE)   # surprise: a matrix!
     age_years  bmi temp
[1,]         0 10.9 35.2
[2,]        84 60.0 40.8

Extra arguments (na.rm = TRUE) go after the function name. sapply() guesses the shape of the result: a vector, a matrix, or a list. That guessing is why purrr has map_dbl(), map_chr(), and friends, which always return the type their name says. For your own functions, the base R shorthand is \(x) mean(x, na.rm = TRUE), the same idea as ~ mean(.x, na.rm = TRUE).

Key points

  • Write it once, run it many times: if you copy and paste code more than twice, write a function with function().
  • A function takes arguments (which can have default values) and returns the result of its last line. Re-run the block after every change.
  • Never give an argument the same name as a column — use district_name, not district.
  • if / else works on one value (great for input checks with stop()); if_else() works on a whole column.
  • A for loop repeats a whole task for each value; create an empty container before the loop to keep results.
  • map() returns a list, map_dbl() a number vector, and walk() just does something (like saving files) for each element. In base R code you will see lapply() (always a list) and sapply() (it guesses the shape).
