Part 2: Writing your first function

Why write functions?

If you copy and paste code more than twice, write a function. The tools for that, function(), if, else, for, and stop(), are all base R: they’re built into R, so they need no package. Functions:

  • avoid copy-paste mistakes (change it once, fixed everywhere)
  • give a task a clear name (c_to_f() says what it does)
  • make your scripts shorter and easier to read

The shape of a function

👀 Follow along 2.1 — Write c_to_f(temp_c) and test it on 38 and on c(36.8, 38.5, 40.1) (the next two code blocks).

c_to_f <- function(temp_c) {
  temp_c * 9 / 5 + 32
}
  • c_to_f is the name — you save a function with <- like any object. Run the whole block to create it; then it appears in the Variables pane
  • temp_c is the argument — the input. Inside the function, it is whatever value you pass in
  • The code between { } is the body
  • The function returns the result of its last line
c_to_f(38)
[1] 100.4
c_to_f(c(36.8, 38.5, 40.1))   # it's vectorized, because the maths inside is
[1]  98.24 101.30 104.18
Note🔍 What this code does
  • c_to_f(38) runs the body with temp_c set to 38: 38 × 9 / 5 + 32 = 100.4.
  • c_to_f(c(36.8, 38.5, 40.1)) converts all three at once: 98.24, 101.3, and 104.18. You didn’t write a loop: *, /, and + already work on every value in a vector, so your function does too.
  • temp_c only exists while the function runs. It doesn’t appear in the Variables pane.

Because it’s vectorized, it works on a whole column inside mutate():

👀 Follow along 2.2 — Use c_to_f() inside mutate() to add temp_f to linelist.

linelist %>%
  mutate(temp_f = c_to_f(temp)) %>%
  select(case_id, temp, temp_f) %>%
  head(3)
  case_id temp temp_f
1  5fe599 36.8  98.24
2  8689b7 36.9  98.42
3  11f8ea 36.9  98.42
Note🔍 What this code does
  • mutate(temp_f = c_to_f(temp)) gives the whole temp column to c_to_f() and stores the answers in a new column, temp_f. 36.8 °C becomes 98.24 °F.
  • select() and head(3) just keep the output short. linelist itself doesn’t change, because the result isn’t saved with <-.

Default values

Give an argument a default with =. You can change it, but you don’t have to:

👀 Follow along 2.3 — Add a digits = 1 default argument with round().

c_to_f <- function(temp_c, digits = 1) {
  round(temp_c * 9 / 5 + 32, digits)
}

c_to_f(38.37)              # uses digits = 1
[1] 101.1
c_to_f(38.37, digits = 0)  # overrides it
[1] 101
Note🔍 What this code does
  • This new c_to_f() replaces the old one, because it’s saved under the same name.
  • digits = 1 inside function() sets a default. c_to_f(38.37) doesn’t mention digits, so it uses 1 and gives 101.1.
  • c_to_f(38.37, digits = 0) overrides the default and rounds to a whole number: 101.
  • Inside the body, round(..., digits) passes your choice on to round().
WarningCommon mistakes
  • Changing the function but not re-running the block: R still uses the old version.

Note📖 Good to know
  • Functions you write live in R’s memory, like any object. They’re gone when R restarts, so keep them in your script, near the top, and run them before you use them.
  • Give functions names that say what they do, such as make_epicurve() or c_to_f(). Avoid names that R already uses, like mean or c: your version would hide the original.
  • In other people’s code you may see return(x). It ends the function and gives back x. Without it, the function returns its last line. Both are fine.

Part 3: Functions that use data

A calculation used in many places

👀 Follow along 3.1 — Write pct(x, digits = 1), which returns round(mean(x, na.rm = TRUE) * 100, digits), and use it in summarise() by hospital.

pct <- function(x, digits = 1) {
  round(mean(x, na.rm = TRUE) * 100, digits)
}

linelist %>%
  group_by(hospital_name) %>%
  summarise(
    n         = n(),
    pct_death = pct(outcome == "Death"),
    pct_fever = pct(fever == "yes")
  )
# A tibble: 7 × 4
  hospital_name                     n pct_death pct_fever
  <chr>                         <int>     <dbl>     <dbl>
1 Central Hospital                454      42.5      77.3
2 HMO Health                      280      44.3      92.9
3 Military Hospital               896      44.5      79  
4 Other/Unknown                  2354      42.7      77.3
5 Premiere Health                 274      47.1      94.5
6 Regional Medical center        1771      44.6      76.7
7 St. Mark's Maternity Hospital   422      47.2      75.8

Compare with Session 5, where we wrote round(mean(...) * 100, 1) every time.

Note🔍 What this code does
  • pct() expects a vector of TRUE and FALSE. The mean() of TRUE/FALSE values is the share that are TRUE (TRUE counts as 1, FALSE as 0). * 100 makes it a percentage, and na.rm = TRUE skips missing values.
  • outcome == "Death" is TRUE for every patient who died, so pct(outcome == "Death") is the percentage who died: 44.5% at Military Hospital.
  • group_by(hospital_name) makes summarise() do this once per hospital, giving 7 rows (including Other/Unknown).

A function that takes a data frame

👀 Follow along 3.2 — Write hospital_summary(data, hospital) and try it on two hospitals.

hospital_summary <- function(data, hospital) {
  data %>%
    filter(hospital_name == hospital) %>%
    summarise(
      n         = n(),
      pct_death = pct(outcome == "Death")
    )
}

hospital_summary(linelist, "Military Hospital")
    n pct_death
1 896      44.5
hospital_summary(linelist, "Central Hospital")
    n pct_death
1 454      42.5

hospital is an argument holding a value (the hospital’s name), so it can go straight into filter().

Note🔍 What this code does
  • hospital_summary() takes two arguments: the data, and the name of one hospital.
  • Inside, filter(hospital_name == hospital) keeps that hospital’s rows. summarise() then counts them and works out the death percentage with your own pct() function. A function can use other functions you wrote, as long as you’ve run them first.
  • Same function, different input: Military Hospital has 896 cases (44.5% died) and Central Hospital has 454 (42.5%).
Note🤔 Think about it: it ran without an error, but is it right?

Here the hospital name has a small typo, a lower-case “h”:

hospital_summary(linelist, "Military hospital")
  n pct_death
1 0       NaN

No error and no warning, but 0 cases and a death percentage of NaN (“not a number”: 0 divided by 0). filter() found no hospital called “Military hospital”, because R treats upper and lower case as different letters. In a longer script, a 0 like this can slip into a report unnoticed. In Part 4 you’ll see how to make a function stop when its input doesn’t make sense.

A function that makes a plot

👀 Follow along 3.3 — Write make_epicurve(data, hospital), which returns a weekly epicurve for one hospital, with the hospital’s name in the title.

make_epicurve <- function(data, hospital) {
  data %>%
    filter(hospital_name == hospital, onset_date >= as.Date("2014-01-01")) %>%
    ggplot(aes(x = onset_date)) +
    geom_histogram(binwidth = 7, fill = "#2a78d6", color = "white") +
    labs(
      title = paste("Weekly cases:", hospital),
      x     = "Week of onset",
      y     = "Number of cases"
    ) +
    theme_minimal()
}

make_epicurve(linelist, "Military Hospital")

paste("Weekly cases:", hospital), a base R function, builds the title from the argument, so every plot gets the right title.

Note🔍 What this code does
  • The body is an ordinary plot pipeline. filter() keeps one hospital, and geom_histogram(binwidth = 7) puts each week’s cases into one bar.
  • onset_date >= as.Date("2014-01-01") also drops onset dates before 2014, which would stretch the time axis back to 2012.
  • A function returns its last value, and here that’s the plot, so make_epicurve(linelist, "Military Hospital") draws it. You could also save it first: p <- make_epicurve(linelist, "Military Hospital").
WarningCommon mistake: name the argument district_name, not district

Don’t give an argument the same name as a column! In

function(data, district) { data %>% filter(district == district) }

R compares the district column with itself, so every row is kept — no error, just the wrong answer. Name the argument district_name instead: filter(district == district_name).

Part 4: if / else

if runs code only when a condition is TRUE. else runs when it’s FALSE:

👀 Follow along 4.1 — Write fever_status(temp) with if / else, and test it on 39.2 and 36.9.

fever_status <- function(temp) {
  if (temp >= 38) {
    "fever"
  } else {
    "no fever"
  }
}

fever_status(39.2)
[1] "fever"
fever_status(36.9)
[1] "no fever"
Note🔍 What this code does
  • if (temp >= 38) asks one yes/no question. When the answer is TRUE, R runs the code in the first { } and returns “fever”. When it’s FALSE, R runs the else { } part and returns “no fever”.
  • 39.2 is at least 38, so it’s “fever”. 36.9 isn’t, so it’s “no fever”.

if works on ONE value

👀 Follow along 4.2 — What happens with fever_status(c(39.2, 36.9))?

fever_status(c(39.2, 36.9))
Error in `if (temp >= 38) ...`:
! the condition has length > 1
Note🔍 What this code does
  • With two temperatures, temp >= 38 gives two answers (TRUE, FALSE), but if can only take one. R stops with “the condition has length > 1”.
  • This error is on purpose: it shows that if handles one value at a time.

if asks one yes/no question. For a whole column, use the vectorized if_else() from Session 2:

👀 Follow along 4.3 — The vectorized version with if_else(), used in mutate() on linelist.

fever_status <- function(temp) {
  if_else(temp >= 38, "fever", "no fever")
}

fever_status(c(39.2, 36.9))
[1] "fever"    "no fever"
linelist %>%
  mutate(fever_measured = fever_status(temp)) %>%
  count(fever_measured)
  fever_measured    n
1          fever 4976
2       no fever 1324
3           <NA>  151
Note🔍 What this code does
  • if_else(temp >= 38, "fever", "no fever") checks every value and picks an answer for each, so this fever_status() works on a whole vector: 39.2 and 36.9 give “fever” and “no fever”.
  • In mutate(), it runs on the whole temp column: 4976 “fever”, 1324 “no fever”, and 151 NA where the temperature is missing. if_else() keeps missing values missing.
  • This version replaces the one-value version, because it has the same name.

Where if shines: checking inputs

if is perfect for questions with one answer, like “is the input a number?”. stop() ends the function with a helpful error message:

👀 Follow along 4.4 — Add an input check with stop() to c_to_f(), and try c_to_f("38").

c_to_f <- function(temp_c, digits = 1) {
  if (!is.numeric(temp_c)) {
    stop("temp_c must be a number, not ", class(temp_c))
  }
  round(temp_c * 9 / 5 + 32, digits)
}

c_to_f("38")
Error in `c_to_f()`:
! temp_c must be a number, not character
Note🔍 What this code does
  • is.numeric(temp_c) asks “is this a number?”. The ! turns the answer around, so the if is TRUE when the input is not a number.
  • stop() then ends the function straight away with your message. class(temp_c) adds the type that was given: “temp_c must be a number, not character”.
  • "38" is in quotes, so it’s text, and the function stops before doing any maths. Without the check, R would give a less helpful error: “non-numeric argument to binary operator”.

A shorter check: stopifnot()

stopifnot(), also base R, does the if and the stop() in one line: it stops unless the condition is TRUE. It fixes the silent typo from Part 3 (reading only, you don’t need to type this):

hospital_summary <- function(data, hospital) {
  stopifnot(hospital %in% data$hospital_name)
  data %>%
    filter(hospital_name == hospital) %>%
    summarise(
      n         = n(),
      pct_death = pct(outcome == "Death")
    )
}

hospital_summary(linelist, "Military Hospital")   # works: 896 cases
hospital_summary(linelist, "Military hospital")   # stops with an error
Note🔍 What this code does
  • hospital %in% data$hospital_name is TRUE when the name you gave appears in the hospital_name column. “Military Hospital” does, so the function runs as before.
  • “Military hospital” doesn’t, so stopifnot() stops the function with: hospital %in% data$hospital_name is not TRUE. An error you can see is better than a 0 you might miss.
  • For a friendlier message, name the condition: stopifnot("hospital not found" = hospital %in% data$hospital_name) stops with “hospital not found”.

Part 5: for loops

A for loop runs the same code once for each value in a vector. Here is the smallest possible loop (reading only, you don’t need to type this):

for (h in c("Central Hospital", "Military Hospital")) {
  print(h)
}
[1] "Central Hospital"
[1] "Military Hospital"

Read it as: “for each h in this vector, run the code between { }”. h takes each value in turn.

Note🔍 What this code does
  • The first time through, h is “Central Hospital”; the second time, “Military Hospital”. Then the loop ends.
  • print(h) shows the current value. You can call the loop variable anything; h is short for hospital.

Loop over every hospital

👀 Follow along 5.1 — Make the hospitals vector (without “Other/Unknown”), then loop and print the number of cases at each.

hospitals <- linelist %>%
  filter(hospital_name != "Other/Unknown") %>%
  distinct(hospital_name) %>%
  pull(hospital_name) %>%
  sort()

hospitals
[1] "Central Hospital"              "HMO Health"                   
[3] "Military Hospital"             "Premiere Health"              
[5] "Regional Medical center"       "St. Mark's Maternity Hospital"
for (h in hospitals) {
  n_cases <- sum(linelist$hospital_name == h)
  print(paste(h, "has", n_cases, "cases"))
}
[1] "Central Hospital has 454 cases"
[1] "HMO Health has 280 cases"
[1] "Military Hospital has 896 cases"
[1] "Premiere Health has 274 cases"
[1] "Regional Medical center has 1771 cases"
[1] "St. Mark's Maternity Hospital has 422 cases"

Inside a loop, results are not printed automatically — use print().

Note🔍 What this code does
  • The pipeline makes a vector of the six hospital names: filter() drops “Other/Unknown”, distinct() keeps each name once, pull() turns the column into a plain vector (all three from the dplyr package), and the base R function sort() puts it in alphabetical order.
  • In the loop, linelist$hospital_name == h is TRUE for each case at hospital h, and sum() counts the TRUEs.
  • paste() joins the pieces into a sentence with spaces between them, and print() shows it: “Central Hospital has 454 cases”.

  • case_counts <- c() makes an empty vector before the loop.
  • Each time through, case_counts[h] <- ... adds one count, labelled with the hospital’s name.
  • After the loop, case_counts holds all six counts, from Central Hospital (454) to St. Mark’s Maternity Hospital (422). Unlike printed output, you can keep using them.

The payoff: one epidemic curve per hospital

👀 Follow along 5.3 — The payoff: loop over hospitals and ggsave() one epicurve each to outputs/.

for (h in hospitals) {
  p <- make_epicurve(linelist, h)
  file_name <- paste0("epicurve_", make_clean_names(h), ".png")

}
  • make_clean_names(), from the janitor package, turns “St. Mark’s Maternity Hospital” into st_marks_maternity_hospital — safe for a file name
  • paste0() glues the pieces with no spaces into epicurve_st_marks_maternity_hospital.png
  • Six files, one loop. Next week, re-run it with the new data — check the Explorer to see the new files in outputs/
Note🔍 What this code does
  • Each time through, p <- make_epicurve(linelist, h) makes that hospital’s plot and stores it in p.
  • ggsave() saves p in outputs/ under the new file name, as an 8 × 5 inch image at 300 dpi (print quality).

mutate(), summarise() with group_by(), and across() all repeat work for you. In R, reach for those first; write a loop when you need to repeat a whole task, like making and saving a plot.

make_measles_epicurve <- function(data, district_name) {
  data %>%
    filter(district == district_name, !is.na(report_date)) %>%
    ggplot(aes(x = report_date)) +
    geom_histogram(binwidth = 7, fill = "#2a78d6", color = "white") +
    labs(
      title = paste("Weekly measles cases:", district_name),
      x     = "Week of report",
      y     = "Number of cases"
    ) +
    theme_minimal()
}

districts <- c("Central", "East", "North", "South", "West")

for (d in districts) {
  p <- make_measles_epicurve(measles, d)

The loop creates five files in outputs/: measles_central.png, measles_east.png, measles_north.png, measles_south.png, and measles_west.png. Again, the argument is district_name, not district.

Note📖 Good to know
  • Fixing a loop that goes wrong: set the loop variable by hand, for example h <- hospitals[1], then run the lines inside the loop one at a time. You’ll see exactly where it breaks.
  • After the loop, the loop variable keeps its last value: here, h is “St. Mark’s Maternity Hospital”.
  • To loop over positions (1, 2, 3, …) instead of values, use for (i in seq_along(hospitals)), then hospitals[i] inside the loop.

Part 6: Iteration the tidyverse way: map() and walk()

The purrr package (part of the tidyverse) does what loops do, in one line:

  • map(x, f) — run f on each element of x and return a list of results
  • map_dbl() — the same, but return a number vector
  • walk(x, f) — run f on each element for its side effect (like saving a file), return nothing

👀 Follow along 6.1 — map_dbl() for the mean of age_years, bmi, and temp.

# The mean of three columns
linelist %>%
  select(age_years, bmi, temp) %>%
  map_dbl(~ mean(.x, na.rm = TRUE))
age_years       bmi      temp 
 16.05732  30.59385  38.58784

A data frame is a list of columns, so map_dbl() runs once per column. ~ mean(.x, na.rm = TRUE) is a short function: .x is the current element — the same ~ .x you used with across() in Session 3.

Note🔍 What this code does
  • select() keeps three columns. map_dbl() then runs mean(.x, na.rm = TRUE) on each one, with .x standing for the current column.
  • The result is a number vector with one named value per column: a mean age of about 16.1 years, a mean BMI of about 30.6, and a mean temperature of about 38.6 °C.

👀 Follow along 6.2 — map() to make a list of epicurves, one per hospital; look at the first.

# A list of six plots
epicurves <- map(hospitals, ~ make_epicurve(linelist, .x))
length(epicurves)
[1] 6
epicurves[[1]]
Tip🧩 Reading a function call

Here is the map() line you just ran, taken apart:

epicurves <- map(hospitals, ~ make_epicurve(linelist, .x))

Piece What it is What it does
epicurves the name of a new object holds the result
<- the assignment arrow saves the result in epicurves
map(...) a function from the purrr package runs a function once for each element, and returns a list
hospitals the first argument of map() the vector to go through: six hospital names
~ make_epicurve(linelist, .x) the second argument: a short, nameless function what to do with each element
.x a placeholder the current hospital name, a different one each time

map() takes the first hospital, puts it in .x, runs make_epicurve(linelist, "Central Hospital"), and keeps the plot. Then it does the same for the next hospital, and so on. Read it aloud as: “for each of the hospitals, make an epicurve, and collect them in epicurves.”

Note🔍 What this code does
  • map() runs make_epicurve(linelist, .x) six times, once per hospital, and collects the six plots in a list called epicurves.
  • length(epicurves) is 6. epicurves[[1]] takes the first plot (Central Hospital) out of the list and draws it. [[ ]] pulls one element out of a list, as in Session 4.

👀 Follow along 6.3 — walk() to save them all (the same as the Part 5 loop).

# Save them all: the same as the for loop in Part 5, in one call
walk(hospitals, ~ ggsave(
  here("outputs", paste0("epicurve_", make_clean_names(.x), ".png")),
  plot = make_epicurve(linelist, .x), width = 8, height = 5, dpi = 300
))
Note🔍 What this code does
  • walk() goes through hospitals like map(), but keeps nothing. It’s for work you do for its effect, like saving files.
  • For each hospital .x, ggsave() makes the plot and saves it under the same file name as the Part 5 loop, so you get the same six files.
NoteLoop or map()?

Both are fine! Loops are easier to read when you’re starting out; map() is shorter and is what you’ll see in modern R code. Choose the one you can read.

Note🔁 The base R way: lapply() and sapply()

Base R’s apply family does the same job, and you will see it everywhere in older code, help pages, and bioinformatics packages (Bioconductor):

purrr base R returns
map(x, f) lapply(x, f) a list
map_dbl(x, f) sapply(x, f) (or vapply(x, f, numeric(1))) a vector, usually

Here are both on age_years, bmi, and temp, with mean and with range (reading only, you don’t need to type this). Which one returns a matrix?

three_cols <- linelist[, c("age_years", "bmi", "temp")]

sapply(three_cols, mean, na.rm = TRUE)    # like map_dbl()
age_years       bmi      temp 
 16.05732  30.59385  38.58784 
lapply(three_cols, range, na.rm = TRUE)   # like map(): a list
$age_years
[1]  0 84

$bmi
[1] 10.9 60.0

$temp
[1] 35.2 40.8
sapply(three_cols, range, na.rm = TRUE)   # surprise: a matrix!
     age_years  bmi temp
[1,]         0 10.9 35.2
[2,]        84 60.0 40.8
Note🔍 What this code does
  • linelist[, c("age_years", "bmi", "temp")] keeps three columns with base R subsetting: all rows (nothing before the comma), these columns.
  • sapply(three_cols, mean, na.rm = TRUE) gives one number per column, the same as map_dbl(). mean has no brackets, because you hand over the function itself instead of running it.
  • lapply(three_cols, range, na.rm = TRUE) gives a list with two numbers (smallest and largest) per column: for example, ages run from 0 to 84.
  • sapply(three_cols, range, na.rm = TRUE) also gets two numbers per column, so it quietly builds a matrix with 2 rows and 3 columns.

Extra arguments (na.rm = TRUE) go after the function name. sapply() guesses the shape of the result: a vector, a matrix, or a list. That guessing is why purrr has map_dbl(), map_chr(), and friends, which always return the type their name says. For your own functions, the base R shorthand is \(x) mean(x, na.rm = TRUE), the same idea as ~ mean(.x, na.rm = TRUE).

Key points

  • Write it once, run it many times: if you copy and paste code more than twice, write a function with function().
  • A function takes arguments (which can have default values) and returns the result of its last line. Re-run the block after every change.
  • Never give an argument the same name as a column — use district_name, not district.
  • if / else works on one value (great for input checks with stop() or stopifnot()); if_else() works on a whole column.
  • Code that runs without an error can still give a wrong answer: a typo in a value gives 0 rows, not an error. Check your results, and let functions check their inputs.
  • A for loop repeats a whole task for each value; create an empty container before the loop to keep results.
  • map() returns a list, map_dbl() a number vector, and walk() just does something (like saving files) for each element. In base R code you will see lapply() (always a list) and sapply() (it guesses the shape).
