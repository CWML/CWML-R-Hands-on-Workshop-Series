Part 1: Project folders and here()

Why keep everything in one project folder?

  • Organization: data, scripts, and outputs live in one folder with a predictable structure (raw_data/, processed_data/, student_scripts/)
  • Reproducibility: the project works on any computer — yours, a collaborator’s, future you’s
  • Shareable: zip the folder and send it, or put it on GitHub

Open the project folder for this class

  1. Download the workshop folder and save it somewhere you can find it (not your Downloads folder)
  2. In Positron, choose File → Open Folder…, select the CWML-R-Hands-on-Workshop-Series folder, and click Open. Positron uses that folder as the working directory
  3. Check the Explorer on the left: it should list the workshop files (raw_data, student_scripts, …)
TipYour own projects later

Make a new folder for each project (with subfolders like raw_data/ and scripts/), and open it in Positron with File → Open Folder…. Add an empty file called .here at the top so here() always finds it. (RStudio users: File → New Project does the same thing and creates an .Rproj file.)

Relative vs absolute paths

  • Bad (absolute): "/Users/mwegener/Desktop/maybe_here/data.csv" — only works on one computer
  • Good (relative): here("raw_data", "data.csv") — works on any computer that has the project folder

here() finds the top of the project folder (it looks for a .here file, which the workshop folder has) and builds the path from there.

here::here()                                   # where is the top of my project?
here::here("raw_data", "linelist_raw.xlsx")    # full path to a file inside it

here::here() means “the here() function from the here package”. The :: lets you use a function before loading its package.

Part 2: Installing and loading packages

A package is a collection of functions someone else wrote. There are two steps:

Step Function How often Analogy
Install install.packages() Once per computer Buying a book
Load library() Every time you open R Taking it off the shelf

Install everything for the whole workshop series (skip this if you did the Setup):

install.packages(c("tidyverse", "here", "rio", "janitor", "skimr", "gtsummary", "flextable", "scales"))

Load only what you need today:

library(tidyverse)   # data wrangling (dplyr) and plotting (ggplot2), plus the pipe
library(here)        # file paths that work on any computer
library(rio)         # import() and export() for almost any file type
library(skimr)       # skim() for a quick data summary
library(janitor)     # get_dupes() today; clean_names() in Session 2
WarningCommon mistakes
  • Package names need quotes in install.packages() but not in library().
  • Red text is not always an error! Messages like “Attaching core tidyverse packages” are normal. An error starts with Error.

Part 3: R basics

Objects and the assignment arrow <-

<- stores a value in an object so you can use it later. Read it as “gets”. The object appears in the Variables pane.

my_age <- 35
my_age
[1] 35
my_age + 5
[1] 40

Vectors

c() combines values into a vector. Every value in a vector has the same type.

ages <- c(2, 18, 56, 61)
hospitals <- c("Central Hospital", "Military Hospital", "Other")

mean(ages)
[1] 34.25
length(hospitals)
[1] 3

Functions and arguments

A function does something to its inputs (arguments): function_name(argument1, argument2, ...). Arguments can be named.

round(3.14159)
[1] 3
round(3.14159, digits = 2)
[1] 3.14
TipGetting help

Type ?round in the Console to open the help page for any function.

Data frames

A data frame is a table: each column is a variable (a vector), each row is an observation. The tidyverse version is called a tibble.

patients <- tibble(
  name = c("Ana", "Ben", "Cho"),
  age  = c(34, 51, 27)
)
patients
# A tibble: 3 × 2
  name    age
  <chr> <dbl>
1 Ana      34
2 Ben      51
3 Cho      27
patients$age        # $ pulls out one column
[1] 34 51 27
WarningCommon mistakes
  • R is case-sensitive: Age and age are different
  • Text needs quotes ("Central Hospital"); object names do not (my_age)
  • Every ( needs a ) — Positron highlights the matching pair
  • # starts a comment; R ignores the rest of the line

Part 4: The pipe %>%

The pipe takes the result on its left and passes it into the function on its right. Read it as “and then”. Shortcut: Shift + Cmd + M (Mac) or Shift + Ctrl + M (Windows).

# Without the pipe: read from the inside out
round(mean(ages), 1)
[1] 34.2
# With the pipe: read from left to right — "take ages, and then mean, and then round"
ages %>% mean() %>% round(1)
[1] 34.2
Note

You may also see |> — the pipe built into R itself. For this workshop they do the same thing.

Important✏️ TRY IT (1 min): the pipe

Use the pipe to find the mean of my_temps and round it to 0 decimals.

✅ Check: the answer is 38

NoteShow solution 
my_temps %>% mean() %>% round(0)
[1] 38

Why not 39? R rounds a 5 to the nearest even number (38.5 → 38), a rule used to avoid bias when rounding lots of numbers.

Part 5: Importing data

import() + here()

rio::import() reads almost any file type (.csv, .xlsx, .txt, SPSS, Stata, SAS, …). It works out the type from the file extension, so you only need to learn one function. Save the result with <-, or it only prints to the Console and is gone.

linelist_raw <- import(here("raw_data", "linelist_raw.xlsx"))

The same function works for other file types:

case_info <- import(here("raw_data", "case_info.csv"))   # comma-separated
hosp_info <- import(here("raw_data", "hosp_info.txt"))   # tab-separated text
WarningCommon mistakes
  • File names must match exactly, including capitals and the extension.
  • “Error: No such file” means the folder or file name is misspelled, or the workshop folder isn’t open (check the Explorer on the left).
TipOther import options you may see
  • Base R: read.csv() — older, slower, and needs more settings
  • readr: read_csv() — the tidyverse version, fast and returns a tibble
  • haven: read_sav(), read_dta(), read_sas() — SPSS, Stata, SAS files
  • Excel files with several sheets: import(here("raw_data", "file.xlsx"), which = "Sheet2")

Note🔁 The base R way: table()

You will often see base R’s table() in other people’s code. It counts too, but it hides missing values unless you ask for them:

table(linelist_raw$OUTCOME)                   # where are the missing outcomes?

  Death Recover 
   2898    2213 
table(linelist_raw$OUTCOME, useNA = "ifany")  # there they are: 1493

  Death Recover    <NA> 
   2898    2213    1493

count() always shows NA. With table(), add useNA = "ifany". See Base R ↔︎ tidyverse for more translations.

Key points

  • A project folder plus here() makes file paths work on any computer.
  • Install a package once with install.packages(); load it every session with library().
  • <- saves a value in an object; c() makes a vector; functions take arguments.
  • The pipe %>% means “and then”, so code reads from left to right.
  • import(here("folder", "file")) reads almost any file type.
  • Look before you clean: glimpse(), skim(), count(), filter()/select()/arrange(), is.na(), and duplicated() find the problems.
