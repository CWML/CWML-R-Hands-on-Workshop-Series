Session 2: Cleaning Your Data

The pipe, column names, fixing types and values, recoding categories, new variables, and saving clean data

⬇ Student script ⬇ Solutions ⬇ Workshop folder (ZIP)

Part 2: The pipe %>%

In Session 1, doing two things at once meant putting one function inside another:

head(arrange(linelist_raw, wt_kg), 3)
  Case ID infection date date.onset  hosp date date of outcome OUTCOME Gender
1  6056ba           <NA> 2014-10-20 2014-10-21      2014-11-05   Death      f
2  6056ba           <NA> 2012-10-20 2012-10-21      2012-11-05   Death      f
3  7400b3     2014-10-07 2014-10-12 2014-10-13      2014-10-18   Death      f
                 hospital age age_unit wt_kg ht_cm
1                    <NA>   0    years   -11    24
2              HMO Health   0    years   -11    24
3 Regional Medical Center   0    years   -10    13

You read that from the inside out: arrange the data, then take the head. Every extra step adds another layer of brackets. The pipe %>% writes the same steps in order, from left to right:

linelist_raw %>% arrange(wt_kg) %>% head(3)
  Case ID infection date date.onset  hosp date date of outcome OUTCOME Gender
1  6056ba           <NA> 2014-10-20 2014-10-21      2014-11-05   Death      f
2  6056ba           <NA> 2012-10-20 2012-10-21      2012-11-05   Death      f
3  7400b3     2014-10-07 2014-10-12 2014-10-13      2014-10-18   Death      f
                 hospital age age_unit wt_kg ht_cm
1                    <NA>   0    years   -11    24
2              HMO Health   0    years   -11    24
3 Regional Medical Center   0    years   -10    13

The pipe takes the result on its left and passes it in as the first argument of the function on its right. Read it as “and then”: take linelist_raw, and then arrange it by weight, and then show the first 3 rows.

  • Keyboard shortcut: Shift + Cmd + M (Mac) or Shift + Ctrl + M (Windows)
  • With the pipe, you don’t write the data inside each function: count(linelist_raw, hospital) becomes linelist_raw %>% count(hospital)

Longer pipelines

Put each step on its own line, with the %>% at the end of the line. select() keeps only the columns you name:

linelist_raw %>%
  select(`Case ID`, wt_kg, ht_cm) %>%   # keep three columns
  arrange(wt_kg) %>%                    # sort by weight
  head(5)                               # show the first 5 rows
  Case ID wt_kg ht_cm
1  6056ba   -11    24
2  6056ba   -11    24
3  7400b3   -10    13
4  0fde59   -10    18
5  fca629    -9    24

That is three steps, readable top to bottom. Written the Session 1 way, it would be head(arrange(select(linelist_raw, ...), wt_kg), 5).

Note

You may also see |>, the pipe built into R itself. For this workshop they do the same thing.

WarningCommon mistakes
  • Put %>% at the end of a line, not at the start of the next one. R stops at a complete line, so a line starting with %>% gives an error.
  • Don’t end the last line with %>%: R then waits for another step (a + appears in the Console). Press Esc and remove it.

TipOne step at a time

We build the clean data step by step. Each step takes the current version, changes one thing, and saves it back with <-:

linelist_clean <- linelist_clean %>% STEP()

If your object gets into a bad state, re-run from the first step (linelist_clean <- linelist_raw %>% clean_names()). In Part 8 we put all the steps into one pipeline.

Part 4: Fixing types with mutate()

mutate() creates a new column or overwrites an existing one: mutate(column = what_to_put_in_it). Use the same name to overwrite a column; a new name to add one.

Dates

as.Date() converts text or date-times to dates.

linelist_clean <- linelist_clean %>%
  mutate(
    date_of_infection = as.Date(date_of_infection),
    onset_date        = as.Date(onset_date),
    hospital_date     = as.Date(hospital_date),
    date_of_outcome   = as.Date(date_of_outcome)
  )

linelist_clean %>% select(date_of_infection:date_of_outcome) %>% glimpse()
Rows: 6,604
Columns: 4
$ date_of_infection <date> 2014-05-08, NA, NA, 2014-05-04, 2014-05-18, 2014-05…
$ onset_date        <date> 2014-05-13, 2014-05-13, 2014-05-16, 2014-05-18, 201…
$ hospital_date     <date> 2014-05-15, 2014-05-14, 2014-05-18, 2014-05-20, 201…
$ date_of_outcome   <date> NA, 2014-05-18, 2014-05-30, NA, 2014-05-29, 2014-05…
NoteDates written in other formats

as.Date() expects year-month-day ("2014-05-13"). For other formats, the lubridate package (part of the tidyverse) has functions named after the order: dmy("13/05/2014"), mdy("05/13/2014"), ymd("2014-05-13").

Numbers stored as text

as.numeric() turns text like "56" into the number 56. Text that isn’t a number (like "unknown") becomes NA, and R warns you: “NAs introduced by coercion”. That warning is fine if you expected it.

linelist_clean <- linelist_clean %>%
  mutate(age = as.numeric(age))

class(linelist_clean$age)
[1] "numeric"
WarningCommon mistakes
  • Forgetting the <- at the start: the result prints in the Console but isn’t saved.

Part 5: Fixing values with if_else()

if_else(condition, value_if_TRUE, value_if_FALSE) checks every row and fixes the values that meet one condition.

Ages in months → years

“If the unit is months, divide by 12; otherwise keep the age.”

linelist_clean <- linelist_clean %>%
  mutate(age_years = if_else(age_unit == "months", age / 12, age))

linelist_clean %>%
  filter(age_unit == "months") %>%
  select(age, age_unit, age_years) %>%
  head()
  age age_unit age_years
1  24   months 2.0000000
2  NA   months        NA
3   7   months 0.5833333
4   7   months 0.5833333
5  24   months 2.0000000
6  24   months 2.0000000
Note🤔 Think about it: what would have happened in later analyses if we had skipped this step?

A 6-month-old baby would be counted as 6 years old. All 37 ages recorded in months would be too old, which would shift the age groups and the average age.

Impossible values → missing

Weights of zero or below are impossible. Instead of deleting the whole row (and losing the patient’s age, outcome, and dates), we replace only the bad value with NA.

linelist_clean <- linelist_clean %>%
  mutate(wt_kg = if_else(wt_kg <= 0, NA, wt_kg))

summary(linelist_clean$wt_kg)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max.    NA's 
   1.00   41.00   55.00   52.99   66.00  111.00      34
Note🔁 The base R way: ifelse() (one letter shorter, one big difference)

Base R has ifelse(), and you will see it everywhere. It works the same way until you use it on dates. Say we want an “estimated onset” that uses the hospital date when the onset date is missing:

if_else(is.na(linelist_clean$onset_date), linelist_clean$hospital_date, linelist_clean$onset_date) %>% head(3)
[1] "2014-05-13" "2014-05-13" "2014-05-16"
ifelse(is.na(linelist_clean$onset_date), linelist_clean$hospital_date, linelist_clean$onset_date) %>% head(3)
[1] 16203 16203 16206

ifelse() silently turned the dates into numbers (days since 1 January 1970). if_else() keeps the type, and gives an error instead of a surprise when the two values have different types. That strictness is why we use if_else() in this workshop.

Part 6: Recoding categories with case_when()

case_when() is if_else() for many conditions. R checks each line in order and uses the first one that is TRUE:

case_when(
  condition_1 ~ new_value_1,
  condition_2 ~ new_value_2,
  .default    = value_for_everything_else
)

Gender

linelist_clean <- linelist_clean %>%
  mutate(gender = case_when(
    gender == "m" ~ "male",
    gender == "f" ~ "female"
  ))

str_detect(column, "pattern") is TRUE when the text contains the pattern, so one line catches every misspelling. | means “or”.

linelist_clean <- linelist_clean %>%
  mutate(hospital_name = case_when(
    str_detect(hospital, "Central")           ~ "Central Hospital",
    str_detect(hospital, "Military|Mitylira") ~ "Military Hospital",
    str_detect(hospital, "Regional")          ~ "Regional Medical center",
    str_detect(hospital, "Mark")              ~ "St. Mark's Maternity Hospital",
    str_detect(hospital, "HMO")               ~ "HMO Health",
    str_detect(hospital, "Premier")           ~ "Premiere Health",
    .default = "Other/Unknown"
  ))

NoteOther useful text functions (stringr)

str_to_lower(), str_to_upper(), str_to_title() change capitalization (str_to_title("north") gives "North") · str_trim() removes extra spaces · str_replace(x, "old", "new") replaces text. You may need these for the TRY ITs!

WarningCommon mistakes
  • Use ~ (tilde), not =, between the condition and the new value
  • Put a comma after each line except the last
  • Check every recode with count(old_column, new_column)
Important✏️ TRY IT (4 min): sex and vaccinated

In measles_clean, recode

  • sex: Male / male / M → "male", Female / female / F → "female"
  • vaccinated: Yes / yes / Y → "Yes", No / no / N / NO → "No", Unknown → "Unknown"

Pattern: COLUMN %in% c("VALUE_1", "VALUE_2") ~ "NEW_VALUE"

✅ Check: count(sex) shows female 533, male 642, NA 40; count(vaccinated) shows only No, Unknown, Yes

NoteShow solution 
measles_clean <- measles_clean %>%
  mutate(
    sex = case_when(
      sex %in% c("Male", "male", "M")     ~ "male",
      sex %in% c("Female", "female", "F") ~ "female"
    ),
    vaccinated = case_when(
      vaccinated %in% c("Yes", "yes", "Y")     ~ "Yes",
      vaccinated %in% c("No", "no", "N", "NO") ~ "No",
      vaccinated == "Unknown"                  ~ "Unknown"
    )
  )

Part 7: Creating new variables

BMI

mutate() can calculate a new column from other columns.

linelist_clean <- linelist_clean %>%
  mutate(bmi = round(wt_kg / (ht_cm / 100)^2, 1))

summary(linelist_clean$bmi)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max.    NA's 
  10.90   24.60   32.10   48.09   49.88 1250.00      34
Note🤔 Think about it: a BMI of 1,250?

That is impossible: the heights and weights don’t fit together. Set BMIs outside a plausible range (10–60) to NA.

linelist_clean <- linelist_clean %>%
  mutate(bmi = if_else(bmi < 10 | bmi > 60, NA, bmi))

summary(linelist_clean$bmi)
   Min. 1st Qu.  Median    Mean 3rd Qu.    Max.    NA's 
  10.90   23.20   28.70   30.58   36.50   60.00    1382

About 1,400 BMIs are now NA, because many height and weight values in this teaching dataset are unrealistic. Setting only the bad value to NA (instead of filtering out those rows) keeps everything else we know about each patient.

Age groups

linelist_clean <- linelist_clean %>%
  mutate(age_cat = case_when(
    age_years < 18 ~ "Under 18",
    age_years < 30 ~ "18-29",
    age_years < 40 ~ "30-39",
    age_years < 50 ~ "40-49",
    age_years < 60 ~ "50-59",
    age_years < 70 ~ "60-69",
    age_years < 80 ~ "70-79",
    age_years >= 80 ~ "80+"
  ))

linelist_clean %>% count(age_cat)
   age_cat    n
1    18-29 1487
2    30-39  598
3    40-49  252
4    50-59   78
5    60-69   27
6    70-79    6
7      80+    1
8 Under 18 4055

Because case_when() stops at the first TRUE line, age_years < 30 only catches ages 18–29 (younger ages were already caught by the line above).

count() lists the groups in alphabetical order (“18-29” before “Under 18”). In Session 5 you will learn how to put them in a sensible order with factors.

Note🔁 The base R way: cut()

Base R’s cut() makes groups from numbers by giving the break points. right = FALSE means each group includes its lower limit (18 goes into “18-29”):

cut(linelist_clean$age_years,
    breaks = c(0, 18, 30, 40, 50, 60, 70, 80, Inf),
    labels = c("Under 18", "18-29", "30-39", "40-49", "50-59", "60-69", "70-79", "80+"),
    right  = FALSE) %>%
  table(useNA = "ifany")
.
Under 18    18-29    30-39    40-49    50-59    60-69    70-79      80+ 
    4055     1487      598      252       78       27        6        1 
    <NA> 
     100

The same counts as case_when(), and already in the right order, because cut() returns a factor (Session 5). Forgetting right = FALSE is the classic mistake: then an 18-year-old lands in “Under 18”.

WarningCommon mistakes

Ending with TRUE ~ "80+" (or .default = "80+") puts every patient with a missing age into the 80+ group. Write the last condition out in full (age_years >= 80 ~ "80+") so missing ages stay NA.

Part 8: One pipeline and saving your work

Here is every step as one pipeline. This is the version to keep in a real project: one block that goes from raw data to clean data, so anyone can re-run it and get exactly the same result.

linelist_clean <- linelist_raw %>%
  clean_names() %>%
  rename(
    date_of_infection = infection_date,
    onset_date        = date_onset,
    hospital_date     = hosp_date
  ) %>%
  mutate(
    # Types
    date_of_infection = as.Date(date_of_infection),
    onset_date        = as.Date(onset_date),
    hospital_date     = as.Date(hospital_date),
    date_of_outcome   = as.Date(date_of_outcome),
    age               = as.numeric(age),
    # Values
    age_years = if_else(age_unit == "months", age / 12, age),
    wt_kg     = if_else(wt_kg <= 0, NA, wt_kg),
    gender    = case_when(
      gender == "m" ~ "male",
      gender == "f" ~ "female"
    ),
    hospital_name = case_when(
      str_detect(hospital, "Central")           ~ "Central Hospital",
      str_detect(hospital, "Military|Mitylira") ~ "Military Hospital",
      str_detect(hospital, "Regional")          ~ "Regional Medical center",
      str_detect(hospital, "Mark")              ~ "St. Mark's Maternity Hospital",
      str_detect(hospital, "HMO")               ~ "HMO Health",
      str_detect(hospital, "Premier")           ~ "Premiere Health",
      .default = "Other/Unknown"
    ),
    # New variables
    bmi = round(wt_kg / (ht_cm / 100)^2, 1),
    bmi = if_else(bmi < 10 | bmi > 60, NA, bmi),
    age_cat = case_when(
      age_years < 18 ~ "Under 18",
      age_years < 30 ~ "18-29",
      age_years < 40 ~ "30-39",
      age_years < 50 ~ "40-49",
      age_years < 60 ~ "50-59",
      age_years < 70 ~ "60-69",
      age_years < 80 ~ "70-79",
      age_years >= 80 ~ "80+"
    )
  )

Save your work

export() is the opposite of import(). Save cleaned data to processed_data/ — never over the raw file.

export(linelist_clean, here("processed_data", "linelist_clean.rds"))

.rds is R’s own file format. It keeps everything exactly as it is in R — dates stay dates and missing values stay NA — so it’s the best choice for a file you will open in R again. (We compare .rds and .csv in Session 3.)

Key points

  • The pipe %>% means “and then”: data %>% step_1() %>% step_2() reads in order, left to right.
  • Never edit the raw data file — every fix happens in code, so anyone can re-run it.
  • clean_names() fixes every column name at once; rename(new = old) changes one.
  • mutate() creates or overwrites columns; as.Date() and as.numeric() fix types.
  • if_else() fixes values that meet one condition; case_when() handles many, checked in order. Use NA to blank out impossible values instead of deleting rows.
  • str_detect() and str_to_title() catch misspellings and inconsistent capitals; check every recode with count(old, new).
  • Keep one pipeline from raw to clean data, and save the result with export() as .rds in processed_data/.
