Note🤔 Think about it: is every missing value a mistake?

No!

  • date_of_outcome is missing for patients who have not had an outcome yet — that is real information
  • bmi is missing where we set impossible values to NA in Session 2
  • case_id missing is a problem: we can’t link these rows to anything else
NoteThree common ways to handle missing values
  1. Leave them as NA — most R functions have na.rm = TRUE to skip them (e.g., mean(x, na.rm = TRUE))
  2. Remove the rows — drop_na(column) removes rows missing that column. Use carefully: you may lose a lot of data
  3. Replace them — e.g., with “Unknown” for categories, so they show up in tables. Never invent numbers without a statistical method (imputation)
# drop_na() example: how many rows would we lose?
nrow(linelist_clean)
[1] 6604
linelist_clean %>% drop_na(bmi) %>% nrow()
[1] 5222

drop_na(bmi) would throw away 1382 patients — more than one in five. That is why we don’t do it here.

Part 4: Duplicates

distinct() keeps one copy of each row that appears more than once.

linelist_final <- linelist_clean %>%
  filter(!is.na(case_id)) %>%     # keep rows that HAVE an ID (! means "not")
  distinct()

nrow(linelist_clean)
[1] 6604
nrow(linelist_final)
[1] 6451

Part 5: Replacing missing values and choosing columns

replace_na() with across()

across() applies the same function to many columns at once. Here: for every text column, replace NA with "Unknown".

linelist_final <- linelist_final %>%
  mutate(across(where(is.character), ~ replace_na(.x, "Unknown")))

linelist_final %>% count(gender)
   gender    n
1 Unknown  304
2  female 3073
3    male 3074
linelist_final %>% count(outcome)
  outcome    n
1   Death 2840
2 Recover 2158
3 Unknown 1453

Read ~ replace_na(.x, "Unknown") as: “for each column (.x), replace its NAs with Unknown”. where(is.character) picks only text columns, so number and date columns keep their NAs.

Note

For a single column: mutate(gender = replace_na(gender, "Unknown"))

We no longer need the original hospital, age, and age_unit columns — hospital_name and age_years replace them. select() keeps columns in the order you list them.

Part 6: Joining datasets

How joins work

A join combines two data frames by matching rows on a key column that both share. A tiny example first:

patients <- tibble(id = c(1, 2, 3), name = c("Ana", "Ben", "Cho"))
labs     <- tibble(id = c(2, 3, 4), result = c("positive", "negative", "positive"))

left_join(patients, labs, by = "id")    # all patients; NA where no lab result
# A tibble: 3 × 3
     id name  result  
  <dbl> <chr> <chr>   
1     1 Ana   <NA>    
2     2 Ben   positive
3     3 Cho   negative
inner_join(patients, labs, by = "id")   # only ids in BOTH
# A tibble: 2 × 3
     id name  result  
  <dbl> <chr> <chr>   
1     2 Ben   positive
2     3 Cho   negative
full_join(patients, labs, by = "id")    # everyone from both
# A tibble: 4 × 3
     id name  result  
  <dbl> <chr> <chr>   
1     1 Ana   <NA>    
2     2 Ben   positive
3     3 Cho   negative
4     4 <NA>  positive
anti_join(patients, labs, by = "id")    # patients with NO lab result
# A tibble: 1 × 2
     id name 
  <dbl> <chr>
1     1 Ana
Join Keeps
left_join() every row of the first data frame
right_join() every row of the second data frame
inner_join() only rows that match in both
full_join() every row from both
anti_join() rows of the first with no match — great for checking

left_join() is the one you will use most: start with your main dataset and add information to it.

Note🔁 The base R way: merge() and %in%

Base R joins with one function, merge(). The all arguments choose the type of join:

merge(patients, labs, by = "id")                # inner join (the default!)
  id name   result
1  2  Ben positive
2  3  Cho negative
merge(patients, labs, by = "id", all.x = TRUE)  # left join
  id name   result
1  1  Ana     <NA>
2  2  Ben positive
3  3  Cho negative
merge(patients, labs, by = "id", all = TRUE)    # full join
  id name   result
1  1  Ana     <NA>
2  2  Ben positive
3  3  Cho negative
4  4 <NA> positive

Watch out: merge() keeps only matching rows unless you say otherwise, and it sorts the result by the key. %in% asks “is each value found in the other vector?”, and gives one TRUE/FALSE per value. It is the base R way to find rows with no match:

patients$id %in% labs$id
[1] FALSE  TRUE  TRUE
patients[!patients$id %in% labs$id, ]   # the same as anti_join()
# A tibble: 1 × 2
     id name 
  <dbl> <chr>
1     1 Ana

%in% is worth learning well: you will use it inside filter() too, for example filter(district %in% c("North", "South")).

Check the join

Always check the number of rows. A left join should not add rows — if it does, the key appears more than once in the second data frame.

nrow(linelist_final)
[1] 6451
nrow(combined_linelist)
[1] 6451
# Cases with no matching case_info (should be 0)
anti_join(linelist_final, case_info, by = "case_id") %>% nrow()
[1] 0
sum(!linelist_final$case_id %in% case_info$case_id)   # the same check in base R
[1] 0
# Is case_id unique in case_info?
case_info %>% get_dupes(case_id) %>% nrow()
[1] 0

Same number of rows before and after, every case matched, and case_id is unique in case_info: the join worked.

Part 7: Exporting

Like import(), export() picks the file type from the extension:

Format Use it for Watch out
.rds Files you will open in R again Only R can open it
.csv Sharing — opens in Excel and any software Column types are lost; missing text comes back as blank "" instead of NA
.xlsx Sharing with Excel users Same as .csv

We save the combined dataset both ways: .rds to keep working in R, .csv to share.

# To keep working in R (Sessions 4–8 start from this file)
export(combined_linelist, here("processed_data", "combined_linelist.rds"))

# To share

export(missing_ids,       here("processed_data", "missing_ids.csv"))
export(combined_linelist, here("processed_data", "combined_linelist.csv"))

Key points

  • Not every NA is a mistake. Count them with colSums(is.na(data)), then decide: leave them, remove the rows (drop_na()), or replace them.
  • Set rows with no ID aside with new IDs (filter(is.na(...)), paste0(), sprintf(), row_number()) instead of losing them.
  • distinct() removes exact duplicate rows; get_dupes(id) finds IDs that appear more than once with different details.
  • mutate(across(where(is.character), ~ replace_na(.x, "Unknown"))) fills missing text in every text column at once; select() chooses and orders columns.
  • left_join(main, other, by = "key") adds columns from a second dataset. Always check the row count and use anti_join() to find rows with no match.
  • export() saves data: .rds to keep working in R, .csv to share.
