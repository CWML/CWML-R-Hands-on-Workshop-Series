# Proposal: one R foundations course for epidemiology *and* biomedical/bioinformatics researchers

**Status:** draft for discussion (Sofia + Max). Nothing in the current course, website, or
student scripts has been changed. Everything is on the local branch
`proposal/epi-biomed-redesign`.

## The problem

The series aims to give students **foundations of programming in R**. It currently serves two
audiences with one dataset type:

- **School of Public Health (epidemiology):** linelists, rates, Table 1, epidemic curves.
  The current course fits them well.
- **Biomedical and bioinformatics researchers:** sample sheets, count/expression **matrices**,
  gene IDs, the same test run on thousands of features. The current course doesn't show them
  their kind of data, and some foundations they need are missing (matrices, lists, statistical tests,
  multiple testing).

Also, base R appears almost only in Session 4, and programming (Session 8) is marked *optional*.

## Principle: how much base R?

Agreed approach (Sofia), and already **applied to the current series on this branch**:

1. **Base R *concepts* are essential and taught properly:** vectors, types, `NA`, `[ ]` / `$` /
   `[[ ]]`, `%in%`, factors, **lists**, functions. The tidyverse is built on them, and statistics
   and Bioconductor are expressed in them.
2. **Base R *alternatives* to tidyverse verbs are reading knowledge only:** a short
   "🔁 The base R way" box where it matters, plus a translation page. Learners should *recognize*
   `merge()`, `tapply()`, `ifelse()`, not master two ways of doing everything.
3. Boxes are chosen where base R and the tidyverse **differ in an instructive way**: `table()` hides
   `NA`, `ifelse()` strips dates, `merge()` is an inner join by default, `factor()` turns typos into
   `NA` silently, `sapply()` guesses the result shape.

## The core idea

> Both groups work with observations × variables, and both run the **same analysis over many
> units**: per district or exposure in epidemiology, per gene or sample in bioinformatics.
> The R underneath is identical. Only the shape of the data at the end (linelist vs matrix)
> and the questions (risk and rates vs differential features) differ.

So: a **shared core** taught to everyone on **one connected dataset**, followed by short
**track sessions**. Every core concept is taught in base R *and* the tidyverse.

## One dataset for both: extend the measles outbreak

We keep the existing measles data and add a **lab substudy**: 137 cases had a blood sample
at diagnosis, and a 60-gene immune panel was measured on each.

| File | Shape | New? |
|---|---|---|
| `raw_data/measles_raw.csv` | 1 row per case | existing |
| `raw_data/district_info.csv` | district populations | existing |
| `raw_data/measles_lab_samples.csv` | sample sheet (sample → patient, date, batch) | **new** |
| `raw_data/measles_immune_panel.csv` | count matrix, 60 genes × 141 samples | **new** |
| `raw_data/gene_annotation.csv` | gene ID → symbol → pathway | **new** |

The new files are generated by `data-raw/make_lab_data.R` (fixed seed, fully reproducible).
Like the existing data, they are fictional and **deliberately messy**:

- Sample sheet: messy column names, `"s017 "` vs `"S017"`, patient IDs missing the hyphen
  (`MS0033`), `b2` vs `B2`, duplicated rows, 3 samples from patients not in the case list
- Matrix: 1 sample with no metadata
- Annotation: Excel converted `MARCH1` → `1-Mar` and `SEPT7` → `7-Sep`; 1 gene unannotated

Built-in signals students can find:

- Vaccinated cases have **lower interferon genes** and **higher antibody genes**
- Cases who died have **higher inflammation genes** (IL6, IL10, CXCL8, S100A8/9)
- Batch B2 has larger library sizes and 12 genes shifted (a **batch effect**)
- Nearly all deaths were unvaccinated, so outcome and vaccination are **confounded**. This is a
  teaching moment that is native to epidemiology and very real in omics.

## Teaching principles (kept from the current course)

- Follow along → ✏️ TRY IT → ✅ Check → sticky notes
- Workshop data for follow-along, measles data for TRY ITs
- Ready-made checkpoint files in `processed_data/` so anyone can join any session
- **New:** each tidyverse skill is followed by a short "🔁 The base R way" box, and
  "do it both ways and compare" exercises where the two disagree for a teachable reason
  (`ifelse()` stripping dates, `table()` hiding `NA`, `merge()` re-sorting rows,
  `m / colSums(m)` recycling the wrong way)
- **Core lessons stay single-version.** Discipline-specific flavor goes in short "⭐ Epi link"
  or "⭐ Bio link" boxes, so we don't maintain two copies of every lesson.

## Questions for discussion

1. **Scope:** a full restructure (as above), or only add Session 5 and the track sessions to the
   current course?
2. **Follow-along data:** the linelist has no lab component. Add a matching lab substudy for it too,
   or use the measles lab data for both follow-along and TRY IT in Session 5?
3. **Effect sizes:** the simulated signals are strong (very small p-values) for teaching clarity.
   Make them subtler and more realistic?
4. **Time:** is 9 sessions realistic, or should the tracks be self-paced pages?
5. **Pipe:** switch to `|>` (base R) throughout, or keep `%>%`?
6. **Session 8:** make programming core rather than optional?
